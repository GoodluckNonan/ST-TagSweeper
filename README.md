# 一鍵去正則保正文（ST-TagSweeper）

把聊天檔案裡所有 `<think>`、`<summary>`、`<plot>` … 這類角括號標籤**直接刪掉，只留正文**的
SillyTavern 擴展。刪除是「破壞式」地寫回聊天檔案本體，之後正則開不開、換哪個預設，都不會再
看到那些東西炸在聊天框裡。

> 平常這些標籤靠正則折疊／隱藏，一旦關掉正則或換預設，`<think>…</think>` 的內容就會原文顯示出來。
> 這個插件就是拿來一次清乾淨的。

---

## 一、安裝

### 方法 A：線上安裝（推薦）

酒館 → **擴展（Extensions）** → **Install extension** → 貼上本專案的 GitHub 網址 → Install，
然後重新整理頁面（F5）。

## 二、怎麼用（四個步驟）

打開面板的方式有三種：

* 點聊天輸入框旁邊的 **魔法棒 🪄 選單 → 一鍵去正則保正文**；
* 按快捷鍵 **`Ctrl + Alt + X`**（可改）；
* 或在擴展設定裡按「開啟面板」。

> **不需要關掉正則。** 插件掃描的是聊天檔案裡的原始 `message.mes`——跟按鉛筆圖示後編輯框顯示的
> **是同一份資料**（酒館只多做了去頭尾空白）。所以正則開著或關著，掃描與清除的結果完全相同。
> 想自己核對的話，看下面的「手動檢測」頁。

### 0️⃣ 手動檢測（懷疑偵測結果時用）

把編輯框裡的內容整段複製，貼進「手動檢測」頁，就會用**完全相同**的引擎即時顯示：

* 偵測到哪些標籤、各出現幾次、目前是「消除 / 白名單 / 不理會」；
* 消除前（紅色＝會被刪掉的部分）與消除後並排對照。

也可以直接輸入訊息編號按「載入」，把那一條的原始內容抓進來比對。

### 1️⃣ 標籤處理

按「掃描」之後，這裡會列出這個聊天檔案裡偵測到的**每一種**標籤，每列左邊有兩個框：

| 框 | 意思 |
| --- | --- |
| 🔴 紅框 | **消除**：連標籤裡的內容一起刪掉 |
| 🟢 綠框 | **加入白名單**：保留內容，只脫掉 `< >` 外殼 |
| 都不勾 | **不理會**：原樣留在訊息裡 |

紅框預設是勾選的（也就是「除了白名單，其他全刪」）。點綠框會自動取消紅框，反之亦然。
句子後面會顯示出現次數、`成對 / 孤兒開 / 孤兒閉`、以及原文樣本，看到不認識的標籤就先看樣本再決定。

上方的「全部消除」可以一次把所有偵測到的標籤設成消除（再按一下取消＝全部改成不理會）。
白名單一律逐個勾選，避免一鍵把垃圾標籤全部保下來。

#### 清單太雜怎麼辦

* **看它來自哪裡**：點每列最左邊的 **▸** 展開，會列出「這個標籤出現在哪幾條訊息」，
  點訊息編號可以直接跳到那一條，跟編輯框對照。常見情況是：你只檢查了最新一條訊息，
  但清單是**整份聊天檔案**統計出來的，雜訊其實來自幾十條前的老訊息。
* **隱藏**：點每列右邊的 **👁** 把不想看到的標籤收起來——**隱藏只影響顯示，處理規則完全不變**
  （照樣消除）。勾「顯示已隱藏」可以叫回來。
* **批次隱藏**：先在上面輸入關鍵字篩選（例如 `Status`），再按「隱藏列出的」，一次把整批收起來。

### 2️⃣ 預覽

勾選「**切換消除前 / 後**」：

* 打勾＝顯示**消除前**的原文，<span style="color:#e0554b">紅色刪節線</span>的部分就是等一下會被刪掉的內容；
* 不打勾＝顯示**消除後**的結果，也就是寫入後聊天框會長的樣子。

紅色邊框的訊息＝高風險變更（整條會被清空、或含有破損標籤造成的連帶刪除），寫入時會額外要求打確認詞。

### 3️⃣ 一鍵清除

按下去之後：

1. 重新掃描一次（避免用到過期的預覽）；
2. 跳出**二次確認**視窗，列出將改寫的訊息數、刪除字數與逐條對照；
3. 若有高風險訊息，要手動輸入 `DELETE` 才會繼續；
4. 自動建立**備份點**；
5. 寫入聊天檔案 → 重新載入 → **校驗**寫入結果。

### 4️⃣ 後悔了怎麼辦

* 面板上的「**回滾上次**」按鈕；
* 或到「**備份點**」頁，對任何一個備份點按「回滾」；
* 備份點也可以「下載」成 `.jsonl`（就是酒館原生的聊天檔格式），或從外部「匯入備份檔」。

回滾前會再自動備份一次「當前狀態」，所以回滾本身也能反悔。

## 三、白名單的規則

白名單＝「**保留內容、只脫外殼**」：

| 設定 | 結果 |
| --- | --- |
| `<plot>正文</plot>`，`plot` 在白名單 | `正文` |
| `<plot>正文</plot>`，`plot` 不在白名單 | （整段刪掉） |
| `<!-- 2.正文 -->`，`!--` 在白名單 | `2.正文` |
| `<!-- 2.正文 -->`，`!--` 不在白名單 | （整段刪掉） |

* 標籤名比對**不分大小寫**，也支援中文標籤名（例如 `<正文>`）；
* 註解一律用 `!--` 當作它的名字（代表所有 HTML 註解）；
* 巢狀也處理得了：`<plot>前<think>推理</think>後</plot>` + 白名單 `plot` → `前後`；
* **白名單內容永久保護**（固定規則，無法關閉）：只要某個標籤被列為白名單，
  它裡面的內容就**永遠不會被消除**——不管外面還包了幾層黑名單標籤：

  | 輸入 | 白名單 | 結果 |
  | --- | --- | --- |
  | `【<a><story>正文</story></a>】` | `story` | `【正文】` |
  | `<a><b><c><story>正文</story></c></b></a>` | `story` | `正文` |
  | `<think>外<plot>內</plot>尾</think>` | `plot` | `內` |

  外層的垃圾標籤本身還是會被刪掉；白名單**內部**的非白名單標籤照樣會刪（例如
  `<plot>正文<think>推理</think>尾巴</plot>` → `正文尾巴`）。
* 內建預設白名單：`plot`、`content`、`正文`。

不知道某個標籤該不該留？到「預覽」頁勾「切換消除前 / 後」看一次就知道了。

## 四、破損輸出怎麼處理（v1.1 重點）

模型偶爾會輸出破損的標籤，例如少了開頭：

```
-- 內容
</think>
<plot>
你醒过神来的时候，窗口正对着一片灰蓝色的天。
</plot>
```

插件的規則是：

* **成對標籤** → 刪掉 `<tag>` 到 `</tag>` 之間的全部內容；
* **落單的結尾標籤 `</tag>`** → 連同「它前面的那一段」一起刪掉（預設行為）；
* **落單的開頭標籤 `<tag>`** → 刪到「下一個標籤之前」或「訊息結尾」（可在設定切換）。

### 難題：刪除起點要從哪裡算？

實際踩到的案例長這樣（推理中間還夾著落單的 `<Admin>`）：

```
懶散状态。它直接承接上一段…
- 回顾<Admin>和<Character>设定，分别列出…
Kokomi：精于算计但又带着女高特有的俏皮…
呼——！没问题了，现在就开始把文字变漫画！
</konatan_planning>          ← 孤兒，開頭沒有東西
<content>
"不要，我累了。"
</content>
```

如果只是「刪到上一個標籤為止」，`<Admin>` 這種**夾在推理中間的殘骸**會把刪除範圍一刀切斷，
導致它前面的推理整段留下來。v1.1 的處理方式是：

**預設「智慧判斷」：往回找最近一個「已經完整收尾」的標籤**（成對標籤的收尾、完整註解、`<br/>` 這類），
中間那些落單的殘骸一律視為破損內容一起吸收 → 推理整塊清掉，正文留著。

三種模式可以在「設定 → 安全防護 → 要從哪裡開始砍」切換：

| 模式 | 行為 | 什麼時候用 |
| --- | --- | --- |
| **上一個「已完整收尾」的標籤**（預設） | 跳過落單殘骸往回找邊界；找不到就從訊息開頭砍 | 絕大多數情況 |
| 一律從訊息開頭砍 | 最激進，孤兒標籤前面的東西全清 | 確定該訊息前半段全是垃圾時 |
| 只砍到上一個標籤（舊行為） | 最保守，容易被中間的殘骸切斷 | 想自己一條一條確認時 |

### 殘留警告（不確定的時候直接講）

演算法再聰明也可能只清掉一半。所以只要**孤兒標籤的刪除範圍前面還留著沒被清掉的內容**，
插件會主動回報，而不是默默放過：

* 「預覽」頁該條訊息會出現 `⚠ 前面可能還有殘留` 的橘色標籤；
* 上方摘要會顯示「殘留警告 N 條」；
* 二次確認視窗也會提醒。

看到警告就切到「消除前」確認一下：如果那些確實是垃圾，把判斷方式改成「一律從訊息開頭砍」再清一次即可。

### 白名單內容保護

**被標成白名單的正文，就算被外面的大標籤整段包住，也會被挖出來保留**（固定規則，不能關）。
這是刪除範圍判斷過寬時的最後一道保險：最糟的情況是「垃圾沒清乾淨」，而不是「正文被吃掉」。

其他安全防護（預設開啟）：

* **跳過程式碼區塊**：``` … ``` 裡面示範用的 `<div>` 不會被誤刪；
* **整理空行**：刪完不會留下一堆連續空行；
* **不清沒有標籤的訊息**：完全沒有 `<` `>` 的訊息一個字都不會動。

## 五、設定項目

| 分類 | 項目 | 說明 |
| --- | --- | --- |
| 掃描範圍 | 包含用戶消息 | 關掉就只清 AI 的消息 |
| | 包含系統消息 | `/sys` 之類 |
| | 同時清理所有 swipe 分支 | 避免切換 swipe 又冒出標籤（預設開） |
| | 同時清理思維鏈欄位 | 處理 `extra.reasoning`（預設關） |
| 安全防護 | 跳過程式碼區塊 / 行內 code | 預設跳過程式碼區塊 |
| | 整理空行 | 預設開 |
| | **白名單內容永久保護** | 固定開啟，不提供關閉 |
| | 落單結尾標籤的處理方式 | 連內容刪 / 只刪標籤 / 不動 |
| | └ **要從哪裡開始砍** | 智慧判斷（預設）/ 從訊息開頭 / 只到上一個標籤 |
| | 落單開頭標籤的處理方式 | 刪到下一個標籤 / 刪到結尾 / 只刪標籤 / 不動 |
| 正則 | 暫時關閉所有正則 | **選用**，平常不需要；手動按鈕，隨時可還原 |
| 正則暫停 | 掃描時暫時關閉所有正則 | 預設開；關閉面板即還原 |
| 快捷鍵 | 啟用 / 自訂 | 預設 `Ctrl+Alt+X`，點輸入框直接按組合鍵即可錄製 |
| 面板 | 記住面板位置 | 面板可用標題列拖曳 |

就算不暫停正則，清除結果也一樣正確——插件讀的是聊天檔案的**原始內容**，跟正則顯示無關。
暫停只是為了讓你在預覽時看到畫面與原文一致。

## 七、常見問題

**Q：會不會把正文誤刪？**
A：有可能，尤其是破損的孤兒標籤。所以流程刻意設計成：一定要先看預覽（紅色＝會被刪的內容）才會寫入，
寫入前還自動備份，寫入後會回讀校驗。真的出事就按「回滾上次」。另外，被列為白名單的內容
**永遠不會被消除**，就算外面包了更大的標籤也一樣。

**Q：清單上那些沒看過的標籤是哪來的？我在編輯框裡沒看到。**
A：插件讀的就是 `message.mes`，跟編輯框同一份資料。點該列最左邊的 **▸** 會列出它出現在哪幾條訊息
（點編號可跳到那一條）；也可以在「手動檢測」頁把編輯框內容貼上去，即時比對。
最常見的原因是：你只檢查了最新一條訊息，但清單是**整份聊天**統計出來的。
不想看到它們就按 **👁** 隱藏（照樣會刪除）。

**Q：可以只清某幾條訊息嗎？**
A：目前是整份聊天檔案一次處理。想保留某種標籤的內容就把它加白名單；
想整條訊息都不動，就把它那個標籤設成「不理會」。

**Q：備份點存在哪？**
A：存在酒館的使用者設定裡（`extension_settings`），預設保留 5 份、單份上限 1.5 MB；
太大的備份會自動改成下載成檔案。酒館自己也會在 `data/<使用者>/backups/` 留聊天備份。

**Q：為什麼掃描時正則被關掉了？**
A：那是「正則暫停」功能，讓你看到真正的原文。關掉面板就會還原。
若上次不小心直接關掉瀏覽器，下次載入插件時會**自動補還原**。

**Q：支援群組聊天嗎？**
A：支援，會逐條顯示發言者名字。

## 八、開發

核心解析邏輯在 `core.js`，不依賴酒館與 DOM，可以直接用 Node 跑測試。
（測試與檢查腳本在原始碼工作區的 `tests/`、`tools/`，不在這個插件資料夾裡。）

```bash
node tests/core.test.mjs        # 解析引擎（42 項）
node tests/chat-flow.test.mjs   # 假 ST context：掃描 / 寫入 / 備份 / 面板渲染 / 手動檢測（22 項）
node tests/package.test.mjs     # 打包完整性（6 項）
node tools/check-ui.mjs         # UI id 與 HTML 標籤平衡檢查
node --test tests/              # 一次跑完
```

授權：跟酒館本體一致，隨意取用。
